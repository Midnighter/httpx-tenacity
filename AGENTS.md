# AGENTS.md

`httpx-tenacity` is a small, typed Python library (>=3.11) that provides retrying
`httpx` and `httpx2` transports built on `tenacity`. `tenacity` is the only required
dependency; each HTTP client is an optional extra (`httpx-tenacity[httpx]`,
`httpx-tenacity[httpx2]`). Docs: https://midnighter.github.io/httpx-tenacity/

## Layout

- `src/httpx_tenacity/`: the client-independent core, which imports no HTTP client.
  - `retry_policy.py`: the `RetryPolicy` protocol and the default `SmartRetryPolicy`
    that `create()` uses to build the tenacity retrying instance.
  - `retry_callback.py`, `wait.py` (`smart_wait`, a `wait_random_exponential` subclass):
    helpers the policies are built from.
  - `_types.py`: private types shared by both integrations (the structural `Response`
    protocol, `SocketOption`, `CertTypes`).
  - `httpx/`, `httpx2/`: one integration per HTTP client. Each has
    `tenacious_transport.py` and `async_tenacious_transport.py` (sync and async
    transports, keep the two in step), `types.py` (the client-specific
    `*HTTPTransportKeywordArguments` and proxy types), and an `__init__.py` that
    guards the import and exports the public symbols.
  - `_version.py` is generated by hatch-vcs; never edit it.
- `tests/unit`, `tests/acceptance`: pytest suites (anyio). `tests/conftest.py` holds
  the `anyio_backend` and `http` fixtures.
- `test-helpers/`: shared test types (`HTTPBackend`), on pytest's `pythonpath`.
- `tests/typing`: mypy examples for both integrations, checked by
  `tests/unit/test_typing.py`.
- `tests/distribution`: `check_wheel_metadata.py`, run by `distribution:check`.
- `tests/documentation`: runs every Python block in `README.md` and `docs/**/*.md`.
- `tests/pyodide`: Pyodide compatibility, run by the Pyodide workflows in CI.
- `docs/`: mkdocs-material site with tutorial, API reference and ADRs in `docs/adr/`
  (ADR001-ADR004: retrying via tenacity; composition over inheritance; the retry policy
  protocol; one integration per HTTP client). Record significant design decisions as a
  new ADR with the `adr` skill and link it in `docs/adr/index.md`.
- `docs/api.md` lists the public classes explicitly; add new public symbols there and
  export them from the integration package or the root core, as appropriate.
- `CHANGELOG.md`: Keep a Changelog format; add user-visible changes under `[Unreleased]`.

## Import boundaries

- Only `httpx/` imports `httpx`, and only `httpx2/` imports `httpx2`. The core imports
  neither, so `import httpx_tenacity` works without an HTTP client.
- The integrations never import each other.
- `tests/unit/test_import_contract.py` checks this in fresh interpreters.

## Commands

Everything runs through hatch (environments are pip-compile locked in `requirements/`):

- Style: `hatch run style:check` (pydoclint, `ruff format --check`, `ruff check`);
  auto-fix with `hatch run style:fix` and `hatch run style:format`.
- Types: `hatch run types:check` (mypy, ty, and pyrefly).
- Unit tests (including the typing and import-contract tests): `hatch run +py=3.15
  unit-tests:run`; CI also runs `+py=3.11`.
- Acceptance tests: `hatch run +py=3.15 acceptance-tests:run`
- Documentation tests: `hatch run +py=3.15 documentation-tests:run`
- Docs: `hatch run docs:build` (strict).
- Distribution: `hatch run distribution:check` (builds the package, runs `twine check`,
  and checks the wheel metadata so that neither HTTP client is a required dependency).
- The type, docs and test environments install both extras, so they cover both clients.
- Do not commit changes hatch-pip-compile makes to `requirements/*.txt` unless
  updating dependencies is the task.

## Design rules

- Transports use composition (ADR002): each integration's transports subclass only
  their own client's `BaseTransport` / `AsyncBaseTransport` (`httpx` or `httpx2`) and
  wrap an inner transport plus a tenacity retrying instance. Do not subclass the
  client's `HTTPTransport`.
- Every HTTP-facing change lands in both integrations, sync and async, including the
  lifecycle methods (`close`/`aclose` and the context manager methods).
- Transports pass their own client's `RequestError` to the policy; the two are
  unrelated classes.
- The policies and helpers stay client-independent (ADR003, ADR004): type responses
  with the `Response` protocol from `_types.py`, not an HTTP client's class.
- Keep the package pure Python and Pyodide-compatible.

## Conventions

- Ruff with `select = ["ALL"]`, line length 88. Check `pyproject.toml` before adding
  `noqa` comments.
- Google-style docstrings, enforced by pydoclint. The summary starts on the line after
  the opening quotes (D212 is ignored) and there is no blank line before a class
  docstring. Types are not repeated in docstrings.
- Every source and test file starts with the Apache-2.0 license header (year the file
  was created) and a module docstring.
- Use `from __future__ import annotations`; put typing-only imports under
  `if TYPE_CHECKING:  # pragma: no cover`. Do not add other `# pragma: no cover`
  comments: coverage measures subprocesses (`patch = ["subprocess"]`), so code that
  only subprocess tests run, such as the import guards, still counts as covered.
- Use `# noqa: <CODE>` only with a specific rule code and when the rule truly does not
  apply.
- Async tests use `@pytest.mark.anyio`.
- Fully typed (`py.typed`); mypy, ty, and pyrefly must pass.
- Tests use `assert` and are exempt from some annotation rules. Add or extend tests for
  both the sync and async transports.
- Tests that touch an HTTP client take the `http` fixture from `tests/conftest.py`, an
  `HTTPBackend` that runs the test once with `httpx` and once with `httpx2`. Do not
  import a client at module level in such tests, unless the test needs both clients
  at once (`tests/acceptance/test_coexistence.py`).
- Prefer `typing.NamedTuple` for value objects in test helpers, and `object` over `Any`.
- Typing cases go in `tests/typing`; a line that the type checker must reject ends in
  an `# expect: <mypy error code>` comment.

## Documentation conventions

- Every Python block in `README.md` and `docs/**/*.md` is a complete, standalone script
  that restates its imports; `tests/documentation` executes each one against mock
  transports.
- Async examples define `async def main()` and end with `anyio.run(main)`.
- `docs/index.md` and `docs/tutorial.md` show each example in `=== "HTTPX"` and
  `=== "HTTPX2"` tabs. `README.md` has an HTTPX example only and describes HTTPX2 in
  prose, because GitHub does not render tabs.

## Changes and releases

- Add a user-facing entry under `## [Unreleased]` in `CHANGELOG.md` for every change in
  behavior, API or supported Python versions.
- Use Conventional Commit messages (`fix: ...`, `feat: ...`, `docs: ...`).
- Versions come from git tags via hatch-vcs. Pushing a tag like `1.2.3` triggers the
  release workflow, so do not create or push tags unless asked.
