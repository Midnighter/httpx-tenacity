# AGENTS.md

`httpx-tenacity` is a small, typed Python library (>=3.11) that provides retrying
`httpx` transports built on `tenacity`. Docs: https://midnighter.github.io/httpx-tenacity/

## Layout

- `src/httpx_tenacity/`
  - `tenacious_transport.py`, `async_tenacious_transport.py`: sync and async transports
    (keep the two in step).
  - `retry_policy.py`: the `RetryPolicy` protocol and the default `SmartRetryPolicy`
    that `create()` uses to build the tenacity retrying instance.
  - `retry_callback.py`, `wait.py` (`smart_wait`, a `wait_random_exponential` subclass),
    `types.py`: supporting code.
  - `_version.py` is generated by hatch-vcs; never edit it.
- `tests/unit`, `tests/acceptance`: pytest suites (anyio, pytest-httpx). `tests/pyodide`:
  Pyodide compatibility.
- `tests/documentation`: runs every Python block in `README.md` and `docs/**/*.md`.
- `docs/`: mkdocs-material site with tutorial, API reference and ADRs in `docs/adr/`
  (retrying via tenacity; composition over inheritance). Record significant design
  decisions as a new ADR with the `adr` skill and link it in `docs/adr/index.md`.
- `docs/api.md` lists the public classes explicitly; add new public symbols there and
  export them from `__init__.py`.
- `CHANGELOG.md`: Keep a Changelog format; add user-visible changes under `[Unreleased]`.

## Commands

Everything runs through hatch (environments are pip-compile locked in `requirements/`):

- Style: `hatch run style:check` (pydoclint, `ruff format --check`, `ruff check`);
  auto-fix with `hatch run style:fix` and `hatch run style:format`.
- Types: `hatch run types:check` (mypy, ty, and pyrefly).
- Unit tests: `hatch run +py=3.15 unit-tests:run`
- Acceptance tests: `hatch run +py=3.14 acceptance-tests:run`
- Documentation tests: `hatch run +py=3.15 documentation-tests:run`
- Docs: `hatch run docs:build` (strict).
- Do not commit changes hatch-pip-compile makes to `requirements/*.txt` unless
  updating dependencies is the task.

## Design rules

- Transports use composition (ADR002): they subclass only `httpx.BaseTransport` /
  `httpx.AsyncBaseTransport` and wrap an inner transport plus a tenacity retrying
  instance. Do not subclass `httpx.HTTPTransport`.
- Keep the package pure Python and Pyodide-compatible.

## Conventions

- Ruff with `select = ["ALL"]`, line length 88. Check `pyproject.toml` before adding
  `noqa` comments.
- Google-style docstrings, enforced by pydoclint. The summary starts on the line after
  the opening quotes (D212 is ignored) and there is no blank line before a class
  docstring. Types are not repeated in docstrings.
- Every source and test file starts with the Apache-2.0 license header (year the file
  was created) and a module docstring.
- Use `from __future__ import annotations`; put typing-only imports under
  `if TYPE_CHECKING:  # pragma: no cover`.
- Use `# noqa: <CODE>` only with a specific rule code and when the rule truly does not
  apply.
- Async tests use `@pytest.mark.anyio`.
- Fully typed (`py.typed`); mypy, ty, and pyrefly must pass.
- Tests use `assert` and are exempt from some annotation rules. Add or extend tests for
  both the sync and async transports.

## Changes and releases

- Add a user-facing entry under `## [Unreleased]` in `CHANGELOG.md` for every change in
  behavior, API or supported Python versions.
- Use Conventional Commit messages (`fix: ...`, `feat: ...`, `docs: ...`).
- Versions come from git tags via hatch-vcs. Pushing a tag like `1.2.3` triggers the
  release workflow, so do not create or push tags unless asked.
