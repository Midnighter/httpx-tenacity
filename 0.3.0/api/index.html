Retry policies¶

The following symbols are exposed to the user by the client-independent package root:

  • RetryPolicy
  • SmartRetryPolicy
  • RetryingT

httpx_tenacity ¶

Provide the retry policies that configure the tenacious transports.

This package imports no HTTP client. The transports live in the integration packages, httpx_tenacity.httpx for HTTPX and httpx_tenacity.httpx2 for HTTPX2. Each of them requires its own extra.

RetryingT = TypeVar('RetryingT', tenacity.Retrying, tenacity.AsyncRetrying) module-attribute ¶

The sync or async tenacity retrying class that a retry policy creates.

RetryPolicy ¶

Bases: Protocol

Define the interface of a retry policy.

A tenacious transport's create() factory calls the policy's create() method with the tenacity retrying class it needs, its HTTP client's base exception for failed requests, and its logger.

SmartRetryPolicy ¶

Bases: NamedTuple

Define the default retry policy.

The policy retries request errors and server-side issues. Between attempts, it waits for the time given in a response header when the response has one of the expected status codes, and otherwise uses random exponential backoff.

Attributes:

Minimum wait time between retries.
exponent_base float

The base for the exponential backoff.

The following helpers, which the default policy is built from, are client-independent as well. They are not exported by the package root, so import them from their own modules:

  • smart_wait from httpx_tenacity.wait

httpx_tenacity.wait ¶

Provide custom wait functions.

smart_wait ¶

Bases: wait_random_exponential

Define a wait strategy that smartly backs-off.

This strategy first checks HTTP responses for an expected status code (by default 429) that indicates that the server is busy. If the status code matches, it checks the response header (by default 'Retry-After') for a wait time indication. Otherwise, it uses random exponential backoff.

__call__(retry_state: tenacity.RetryCallState) -> float ¶

Return a wait time in seconds based on response headers or retry state.

When we have a successful outcome, i.e., we received an HTTP response without encountering an exception, and the HTTP status code of the response matches the specified status code, check if the response header indicates a wait time; otherwise use the random exponential strategy to determine the wait time.

__init__(multiplier: float = 1, max: timedelta | float = 60, exp_base: float = 2, min: timedelta | float = 0, status_code: int | tuple[int, ...] = HTTPStatus.TOO_MANY_REQUESTS, header: str = 'Retry-After') -> None ¶

httpx_tenacity.retry_callback ¶

Provide custom retry callback functions.

is_server_side_issue(response: Response) -> bool ¶

Return whether the response indicates a server side issue.

A server side issue is defined as either an HTTP server error code (500 - 599) or too many requests (429).

TenaciousTransport ¶

Bases: BaseTransport

Define the synchronous tenacious (retrying) transport.

This transport consists of a composed transport for handling requests and an appropriately configured tenacity retrying instance.

The transport owns the composed transport, including one that you pass in yourself. Entering, exiting, or closing this transport does the same to the composed transport, in the same way that httpx.Client treats its transport.

create(policy: RetryPolicy | None = None, transport: httpx.BaseTransport | None = None, **kwargs: Unpack[HTTPXHTTPTransportKeywordArguments]) -> TenaciousTransport classmethod ¶

Create an instance of a synchronous tenacious (retrying) transport.

This factory method constructs the instance with an underlying httpx.HTTPTransport. That transport is passed any additional keyword arguments.

The retry policy creates the tenacity retrying instance. The default SmartRetryPolicy retries requests when there are server-side issues and will either wait the time set in a Retry-After response header or use a random exponential backoff.

The returned transport owns the underlying transport, including one passed in as transport, and closes it when it is closed.
